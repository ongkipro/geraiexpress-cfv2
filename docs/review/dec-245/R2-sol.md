| 11 | **P2** | `apps/worker/src/brand/hero/hero-studio-3d.src.js:1476–1486,1564–1567` | **Resizing clears the paused/reduced-motion hero without scheduling a replacement frame.** `handleResize()` updates the camera and calls `renderer.setPixelRatio()` / `renderer.setSize()`, which resize/reset the canvas drawing buffer. Once playback is paused and `settleFrames` reaches zero, `animate()` returns before rendering. Nothing in `handleResize()` invalidates that stopped frame. The resize path is connected to window resize, `ResizeObserver`, and `visualViewport.resize` (`:1473,1849–1856`), so browser resizing, orientation changes, or phone viewport changes can leave the hero blank until playback or another rendering interaction occurs. This is made reachable by the new early return; the previously continuous rendering repainted after resize. **Source-derived repro:** load `/` with reduced motion, wait for the initial settle to finish, then change viewport dimensions while leaving playback paused. The current clock-only tests cannot detect the lost image. | Invalidate/request a static redraw whenever resize changes the drawing buffer, without advancing `sceneClock` or enabling playback. Ensure the responsive camera state is updated too. Add a browser regression that resizes after both ordinary pause and reduced-motion settling, verifies the scene remains rendered, and verifies the clock stays frozen. Rebuild the shipped minified bundle. |
