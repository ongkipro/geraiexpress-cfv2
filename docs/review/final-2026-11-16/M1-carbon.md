2. **P1 — Unnormalized `Host` header in `hostOrigin()` + uncaught `renderTemplate()` throw in `sendOne()` creates a poison-pill `email_outbox` deadlock**
   - **Location:** `apps/worker/src/http/request.ts:12-16`, `apps/worker/src/email/templates.ts:29-33`, `apps/worker/src/email/mailer.ts:77-82`, `128-138`
   - **Failure scenario:** `classify()` (`apps/worker/src/host/classify.ts:116`) normalizes `Host` (lowercasing and stripping trailing `.`), and `sameOriginOk()` (`apps/worker/src/auth/csrf.ts:16`) compares `o.host.toLowerCase() === host.toLowerCase()`, so an unauthenticated `POST /api/app/auth/password/forgot` with `Host: App.GeraiExpress.com` and `Origin: https://app.geraiexpress.com` for any registered email (or an authenticated `login` `security_alert` / `kasir_invite`) succeeds. `hostOrigin()` (`apps/worker/src/http/request.ts:14-15`) copies the raw `Host` header verbatim (`"https://App.GeraiExpress.com"`) into the queued email's `link`.    - **Smallest fix:** Normalize the host in `hostOrigin()` (`apps/worker/src/http/request.ts:12-16`) via `normalizeHost` (preserving only a valid port when present, e.g. `.localhost:8787`), and move `decryptString` / `JSON.parse` / `renderTemplate` inside the `try` block in `sendOne()` (`apps/worker/src/email/mailer.ts:77-82`), marking render/decrypt failures terminal (`finish(..., "failed", ...)`) so one malformed row can never abort a batch.

   - **Location:** `apps/worker/src/do/gerai-vault/index.ts:2240-2261`, `2272-2333`
   - **Failure scenario:** `armOutbox()` (`apps/worker/src/do/gerai-vault/index.ts:2251`) unconditionally executes `setTimer(this.ctx.storage.sql, "daily_stats", Date.now() + 300_000, "earliest")` whenever `vault_timers` and `cashier_shifts` exist. 4. **P1 — Email OTP verification leaks account existence, has a concurrent read-modify-write race + multi-OTP bypass of the 5-wrong-entry lock, and `acceptInvitation` permits unthrottled password guessing**
   - **Location:** `apps/worker/src/auth/flows.ts:56-81`, `84-106`, `337-340`; `apps/worker/src/auth/account/index.ts:55-60`, `83-95`; `apps/worker/src/api/app.ts:130-133`, `193-197`
   - **Failure scenario:**
     1. *Account enumeration:* When `email` already exists in `users`, `requestSignupOtp()` (`flows.ts:62-67`) returns a random `{ otpId }` without inserting an `email_otps` row (and `requestEmailChange()` in `account/index.ts:55-60` does the same). Submitting 5 dummy codes to `POST /api/app/auth/signup/verify` hits `if (!row) throw invalid()` (`flows.ts:92`) and returns `400 OTP_INVALID` on attempt 5 iff the email is registered, vs `429 TOO_MANY_ATTEMPTS` (`flows.ts:104`) iff unregistered.
     2. *Race & per-`otpId` lock bypass:* `verifySignupOtp()` (`flows.ts:89-103`, no IP throttle) and `confirmEmailChange()` (`account/index.ts:83-94`) read `row.attempts` in `SELECT`, compute `row.attempts + 1` in JS, and write `SET attempts = ?`; concurrent requests across isolates overwrite stale `attempts < 5` without locking. Sequentially, `requestSignupOtp()` neither checks `otp-lock:${eh}` nor revokes prior unconsumed `email_otps` for `eh`, allowing 3 active `otpId`s × 4 wrong guesses = 12 wrong entries without triggering the spec 05 §2.1 5-wrong-entry email lock.
     3. *Unthrottled password check on invitation accept:* `acceptInvitation()` (`flows.ts:337-340`, `POST /api/app/auth/invitations/:token/accept`, public, no Turnstile) calls `verifyPassword()` for existing users with zero `login-lock:${eh}`, `login-fail:${eh}`, or `login-ip:${ipHash}` checks and throws before consuming the token, allowing unlimited password brute-force for 7 days via any open invitation token (even while `/auth/login` is locked).
   - **Smallest fix:** Check `lockedUntil` and revoke prior open OTPs in `requestSignupOtp()` / `requestEmailChange()`, insert an unmatchable `email_otps` row (`code_hash = "existing"`) when the address already exists so `/verify` and `/confirm` exhibit identical 5-attempt `429` behavior, replace JS `row.attempts + 1` with atomic `throttle.hit(env.DB, "otp-wrong:" + emailHash, OTP_MAX_WRONG - 1, OTP_LOCK_MS, now)` (plus a per-IP `throttle.hit` on `/auth/signup/verify`), and apply `lockedUntil("login-lock:" + eh)` + `login-ip` + `login-fail:${eh}` inside `if (existing)` in `acceptInvitation()` (`flows.ts:337`).
